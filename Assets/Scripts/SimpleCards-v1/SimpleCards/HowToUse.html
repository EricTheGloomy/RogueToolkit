Unity Card Deck Kit

Deck, hand, discard, exile. Draw, play, target, reshuffle. The kit never learns what an "enemy" is — you tell it what's targetable right now, it validates what the player picked and hands it back, and dealing the damage stays your code's business.

The files

Eight files, one per idea. The first three are what you author with.

  • Card.cs

    One kind of card: cost, targeting, where it goes after playing.

  • CardInstance.cs

    One physical copy, with its own id and its own cost tweak.

  • CardTarget.cs

    Something a card can be pointed at. Your object, your meaning.

  • CardPile.cs

    A stack of cards. Used for all four piles — there's no special hand code.

  • PlayResult.cs

    What happened, with a plain-English reason for any refusal.

  • CardTable.cs

    The four piles, energy, drawing, and the rules about playing.

  • CardLibrary.cs

    The asset your game points at: starting deck, lookup, deck saving.

  • CardExample.cs

    Zero-setup demo. Press Play, read the Console. Delete once it clicks.

Setup, about one minute

  1. Copy the eight .cs files into your project and let Unity compile.

  2. Add the Card Example component to an empty GameObject and press Play.

    You'll see a 10-card deck dealt, four kinds of refusal explained, cards played at a goblin, a card exiling itself and drawing two, and the discard reshuffling when the draw pile runs dry.

  3. Now author your own: right-click → Create → Cards → Card. Set the cost and the targeting.

    Leave Targeting on None for a card that just does something to you.

  4. Create → Cards → Library. Drag every card into All Cards, then build the Starting Deck — dragging the same card in three times is how you get three copies.

    Right-click the Library and pick Check For Problems.

The four piles

All four are the same class. That's most of why this kit is small — there's no special "hand" code, just piles and moving cards between them.

afterPlay on each card decides which arrow it takes: Discard (the usual), Exile, BackToHand, or ToDrawPile.

Kinds of card versus copies of card

The bit most people skip, and then have to retrofit painfully.

A Card asset is a kind of card. A CardInstance is one physical copy — the actual bit of cardboard. A deck with three Strikes in it has one Strike asset and three instances.

Without that split you can't tell one Strike in your hand from another, so you can't discard that one, upgrade this one, or animate them separately. It also gives you a free per-copy cost tweak:

A discount on one copy only
// "This card costs 1 less this fight" - without touching the shared asset,
// so every other copy of Strike in the deck is unaffected.
cardInstance.costChange = -1;

int price = cardInstance.GetCost();   // never goes below 0

You build instances by handing the table a list of card assets — the same asset several times is exactly how you get several copies:

A ten-card starting deck
List<Card> deck = new List<Card>();

for (int i = 0; i < 4; i++) deck.Add(strike);
for (int i = 0; i < 4; i++) deck.Add(defend);
deck.Add(cleave);
deck.Add(planAhead);

table.StartNewGame(deck);   // builds the instances and shuffles

Targeting

The piece that keeps the kit reusable. It never learns what an "enemy" is.

Your game keeps a list of what's targetable right now. Rebuild it whenever something dies or spawns — that's what stops a card being played on a corpse:

Whenever the board changes
void RefreshTargets()
{
    table.availableTargets.Clear();

    foreach (Enemy enemy in aliveEnemies)
    {
        // kind, what to show in the UI, and the real object behind it
        table.availableTargets.Add(new CardTarget("enemy", enemy.displayName, enemy));
    }

    foreach (Ally ally in party)
    {
        table.availableTargets.Add(new CardTarget("ally", ally.displayName, ally));
    }
}

targetKind is your own word — "enemy", "ally", "minion", "card". The kit only compares strings; what they mean is entirely up to you.

Recipe: a turn

The whole loop is four calls.

CombatController.cs
public CardLibrary library;

private CardTable table;

void StartCombat()
{
    table = library.StartNewGame();
    RefreshTargets();
    StartTurn();
}

void StartTurn()
{
    table.RefillEnergy();
    table.Draw(5);
    Redraw();
}

// The "End Turn" button.
public void EndTurn()
{
    table.DiscardHand();

    EnemiesTakeTheirTurn();
    RefreshTargets();      // something may have died

    StartTurn();
}

There's no turn structure baked into the kit on purpose — turns differ too much between games. These are the pieces; the order is yours.

Recipe: the UI

Clicking a card, then clicking a target.

HandUI.cs
private CardInstance selected;   // the card waiting for a target

// 1. Player clicks a card in hand.
public void OnCardClicked(CardInstance card)
{
    if (!table.CanAfford(card))
    {
        Message("Not enough energy.");
        return;
    }

    if (card.card.NeedsATarget() && card.card.targeting != Card.Targeting.All)
    {
        selected = card;
        HighlightTargets(card.card.targetKind);   // glow the valid enemies
        return;
    }

    // Needs nothing picked - play it straight away.
    Resolve(table.Play(card, null));
}

// 2. Player clicks an enemy.
public void OnTargetClicked(CardTarget target)
{
    if (selected == null) return;

    List<CardTarget> chosen = new List<CardTarget>();
    chosen.Add(target);

    Resolve(table.Play(selected, chosen));
    selected = null;
    ClearHighlights();
}

void Resolve(PlayResult result)
{
    if (!result.played)
    {
        // Nothing changed, so just tell them why and carry on.
        Message(result.refusedBecause);
        return;
    }

    ApplyEffect(result);
    Redraw();
}

void Redraw()
{
    energyLabel.text = table.energy + "/" + table.maxEnergy;
    drawCountLabel.text = table.drawPile.Count.ToString();
    discardCountLabel.text = table.discardPile.Count.ToString();

    foreach (CardInstance card in table.hand.GetAll())
    {
        // ...draw a card object, greyed out if !table.CanAfford(card)
    }
}

Because a refusal changes nothing, calling Play speculatively is always safe — you never need to pre-check the rules yourself and risk the two checks disagreeing.

Recipe: card effects

Your own card type, and the one place your game does the work.

AttackCard.cs
using UnityEngine;

[CreateAssetMenu(menuName = "Cards/Attack Card")]
public class AttackCard : Card
{
    public int damage;
    public int block;
    public int drawCards;
    public GameObject hitEffect;
}
Applying it
void ApplyEffect(PlayResult result)
{
    // "as" rather than a straight cast, in case your deck mixes card types.
    AttackCard details = result.card.card as AttackCard;
    if (details == null) return;

    foreach (CardTarget target in result.targets)
    {
        // The object you put in when you built the target list.
        Enemy enemy = (Enemy)target.thing;

        enemy.TakeDamage(details.damage);
        Instantiate(details.hitEffect, enemy.transform.position, Quaternion.identity);

        if (enemy.IsDead()) RefreshTargets();   // keep the list honest
    }

    if (details.block > 0)      player.AddBlock(details.block);
    if (details.drawCards > 0)  table.Draw(details.drawCards);

    // The escape hatch, same as the other kits.
    switch (result.card.card.customTag)
    {
        case "SCREEN_SHAKE": camera.Shake(); break;
    }
}

Note the last one: a card that draws cards works because the card already left your hand before you got the result. That's deliberate, and it's why a "draw 2" card can never draw itself.

Saving a deck

A deck is just a list of IDs, duplicates and all.

Between fights
void SaveRun()
{
    List<string> deck = library.SaveDeck(table.GetEveryCard());

    PlayerPrefs.SetString("deck", string.Join(",", deck.ToArray()));
    PlayerPrefs.Save();
}

void LoadRun()
{
    string stored = PlayerPrefs.GetString("deck", "");
    if (stored == "") { table = library.StartNewGame(); return; }

    List<string> ids = new List<string>(stored.Split(','));

    table = new CardTable();
    table.StartNewGame(library.LoadDeck(ids));
}

Cards carry the same permanent hidden ID as the other kits, so renaming and moving your card assets is safe. A card deleted in an update is skipped rather than crashing, so old saves keep loading.

GetEveryCard() gathers all four piles, so it doesn't matter whether the player quit mid-fight.

Four gotchas

The card leaves your hand before your effects run

By the time you get the PlayResult, the card is already in the discard or exile pile. That's deliberate — a card that says "draw 2 cards" must not be able to draw itself. If you need to know where it went, check the piles, don't assume it's still in hand.

Rebuild availableTargets whenever something dies

The kit refuses a target that isn't on the list, which is what stops a card being played on a corpse — but only if you keep the list honest. Rebuild it after every death and every spawn. It's cheap.

StartNewGame rewinds everything

It clears all four piles and deals a fresh deck. Don't call it to start a turn — that's RefillEnergy and Draw. Same shape of mistake as Play versus Resume in the timeline kit.

Ctrl+D copies a card's hidden ID

Right-click your Library → Check For Problems. It catches that, plus empty slots, starting-deck cards missing from the pool, and cards that need a target but have no targetKind — which can never be played at all.

Outgrowing it

What this deliberately doesn't do.

Card effects as data
Effects are your own C# — the kit only says what was played at what. If you want designers authoring effects in the Inspector, borrow the adventure kit's Effect class; it's built for exactly that.
Cards that play themselves
No triggers or "when you draw this" hooks. Watch for them in your own code around Draw — a general trigger system is a much bigger idea and the usual reason card games get complicated.
Two players
One table means one deck and one hand. For a duel, make two CardTables. They don't know about each other, which is fine — your game code is the referee.
Card upgrades that change stats
costChange is per-copy, but everything else comes from the shared asset. For "upgraded Strike deals 9", make Strike+ a separate asset and swap the instance's card — or add your own fields to CardInstance by subclassing it.
Animating cards between piles
The kit moves cards instantly; your UI can animate afterwards by comparing what changed. Each instance's instanceId is stable, so it's a good key for a dictionary of card objects.
